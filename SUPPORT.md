# Support

## Before asking for help

1. Read [README.md](README.md).
2. Check the relevant document in [docs/README.md](docs/README.md).
3. Search existing GitHub issues and pull requests.
4. Reproduce the problem on the supported runtime before reporting it.

## What to include

For technical questions, include:

- FadeReach commit or release/tag.
- Operating system and runtime versions.
- Relevant command and complete non-sensitive output.
- Expected behavior.
- Actual behavior.
- Minimal reproduction steps.
- Whether the issue affects one tenant/workspace or the whole installation.

**Never include credentials, API keys, session tokens, customer data, private email content, or other secrets.**

## Bug reports

Use the repository's **Bug report** issue form for reproducible product defects.

## Feature requests

Use the **Feature request** issue form and explain the user/problem context, proposed behavior, constraints, and measurable outcome.

## Security issues

Do **not** use a public issue for a suspected vulnerability. Follow [SECURITY.md](SECURITY.md).

## Commercial or managed support

FadeReach is a Tinlance commercial product. Repository support does not imply a managed-service or production SLA. Commercial support arrangements are handled separately by Tinlance Limited.
